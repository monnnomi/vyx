# Передача VYX агенту Fable 5

Подготовлено 10 ноября 2026 года. Этот файл предназначен для агента, запущенного на Mac владельца с доступом к существующей папке `vyx`. Здесь нет секретов или копий пользовательских данных.

## 1. Что тебе передают

VYX — действующее SocialFi-приложение с реальными пользователями. Работай в этом репозитории, а не в родительской папке задачи и не в отдельном дизайн-прототипе.

Владелец хочет дать тебе возможность выполнять его задачи по всему проекту: интерфейс, сервер, база, тесты, интеграции и публикация. Не ограничивай работу косметикой или инструкциями, если запрошена реализация. Самостоятельно доводи обычные обратимые правки до проверяемого результата. Конкретное следующее изменение задаёт владелец; эта передача не означает, что надо самостоятельно запускать все обсуждавшиеся идеи.

Файл не выдаёт системные разрешения. Приложение, в котором ты запущена, должно разрешать чтение/запись этой папки, запуск команд и необходимые сетевые подключения. Доступ текущего чата или другого агента не гарантирует доступ твоего процесса.

## 3. Настройки и секреты

- `.env.local`: подключение общей базы, секрет сессии, адрес сайта и администраторы. Этот файл уже существует и не отслеживается Git.
- `.env.media.local`: локальный комплект настроек, в том числе X OAuth, Blob и cron. Он тоже игнорируется Git. Не считай два файла автоматически синхронизированными или заменой актуальных настроек Vercel.
- В продакшене используются Environment Variables существующего Vercel-проекта. `.env.example` содержит только имена/пустые значения для новой среды.
- Не запускай `cat .env*`, `printenv`, экспорт ключей в ответ или загрузку файлов с секретами. При проверке достаточно показывать имя переменной и наличие значения.
- Не меняй ключи, allowlist администратора, OAuth-права и DNS ради обычной разработки. Если действительно нужен новый доступ, объясни владельцу конкретную причину и используй штатный вход сервиса.
- При необходимости обновить локальные настройки используй существующий проект Vercel и сохраняй их только в игнорируемый файл. Не публикуй их в репозитории и браузерном коде.

## 4. С чего начать

Открой терминал в корне `vyx` и прочитай `AGENTS.md`.

```sh
node --version
git status --short
git log -5 --oneline
gh api repos/monnnomi/vyx --jq '{full_name,default_branch,permissions}'
vercel whoami
vercel inspect https://joinvyx.com
```

Если появились чужие изменения, сохрани их. Не используй сброс, очистку или замену папки свежим шаблоном. Проверяй удалённую ветку перед отправкой; не переписывай историю `main` принудительно.

При этой передаче `vercel project inspect ... --scope monnnomis-projects` однажды вернул `Not able to load teams`, тогда как `vercel inspect https://joinvyx.com` через существующую локальную привязку успешно нашёл production. Такая ошибка сама по себе не означает потерю доступа и не требует создания нового проекта.

Зависимости уже установлены в текущей папке. `npm ci` нужен при их отсутствии или изменении lock-файла. Проект не требует React/Vite/Next.js: браузерные модули подключены обычными `script defer` в `public/index.html`, и их порядок имеет значение.

## 5. Локальная проверка

Изолированный интерфейс со своей одноразовой PGlite-базой и тестовыми X-аккаунтами:

```sh
VYX_QA_PORT=4174 VYX_QA_ENGAGEMENT=1 node test/browser-server.mjs
```

Открой `http://127.0.0.1:4174/test-login`. Для другого тестового аккаунта есть `/test-login-bob`. Эти входы работают только в локальном тестовом сервере, который исключён из публикации. При занятом порте выбери свободный через `VYX_QA_PORT`. Останови свой сервер после проверки.

```sh
npm test
```

Тесты используют PGlite, а не живую базу. Последняя полная проверка приложения перед передачей: 176 passed, 0 failed, 9 ноября 2026 года. При изменении кода это историческая опора; свои проверки выполни и укажи отдельно. Для правок только документации полный прогон не требуется.

`npm start` запускает `scripts/dev.mjs` и подхватывает `.env.local`. На этом Mac там указана общая Neon-база: локальный адрес не превращает её в тестовую. Для обычной визуальной QA используй сервер выше. Реальный локальный OAuth требует зарегистрированного callback и отдельной проверенной конфигурации.

## 7. Действующие особенности продукта

- UI на английском; объяснения владельцу на русском. Компактный мессенджер, удобные комнаты, светлая и графитовая темы, мобильная адаптация.
- Работают X-вход, профили, посты/комментарии, фото/видео/GIF, комнаты, взаимные подписки для DM, поиск, блокировка/мьют, жалобы и админская модерация.
- Пять действующих заданий X дают суммарно 8,500 VP с проверкой через официальный API и идемпотентным начислением. Бюджет проверок — существующий лимит по умолчанию $1/день; обычная QA не требует платных запросов X.
- Реферал закрепляется при первой регистрации нового X-аккаунта. Самоприглашения и уже существующие аккаунты не дают реферала. За реферал сейчас нет отдельной награды VP.
- 50,000 подтверждённых lifetime VP и 3 реферала дают бесплатный NFT; только 50,000 VP — скидку 50%. Прогресс видят владелец профиля и админ. Публичный вайтлист показывает прошедших и их категорию, а не недостающие показатели.
- У сообщений в комнатах/DM 24 реакции, одна на аккаунт/сообщение с заменой и удалением. Посты и сообщения имеют уникальные просмотры: один X-аккаунт, без автора, от секунды видимости; фоновые вкладки не считаются. Списки читателей не публикуются. Просмотры не дают VP.
- Фарм: максимум 700M VP, по 350M на ноябрь и 1–24 декабря 2026 UTC; 300M — промо-резерв. Четырёхчасовые окна и версия v2 описаны в `docs/farming-v2.md`. Подтверждённые награды и историю не пересчитывать задним числом.
- Будущие NFT перепродаются, одинаковые экземпляры складывают бонусы, личного потолка 100% нет. Пример 10 NFT / 500% — не объявленная ставка. Настоящие wallet/contract-проверки и торговля пока не подключены; текущие v2-коэффициенты базовые.
- Halloween-сундук — памятный предмет без VP; выдача закрылась 1 ноября 2026 в 00:00 UTC. Не открывай старую кампанию случайно.
- Видео уже загружаются как вложения до 50 MiB. Специализированные Clips/Shorts, перекодирование и Cloudflare Stream только обсуждались. Их реализация и платное подключение ещё не поручены.
- Текущая общая квота медиа — 512 MiB, включая резерв под сборку; 100 MiB/20 подготовленных файлов на аккаунт за 24 часа. Приватность вложений проверяется на сервере.

## 8. Миграции и публикация

1. Реализуй конкретную задачу, сохраняя действующие доступы и пользовательские данные.
2. Проверь её изолированно; при общих изменениях запусти полный набор тестов и нужную браузерную QA.
3. Новую схему вводи отдельной совместимой миграцией. Сначала проверь повторный запуск на тестовой базе, затем примени необходимую миграцию к живой базе с проверкой сохранности данных. Не используй общий `npm run db:migrate` как бездумный шаг каждой публикации.
4. Зафиксируй только свои файлы. Для задач с публикацией отправь проверенные изменения в `main` существующего `monnnomi/vyx` — это запускает Vercel production.
5. Проверь успешный статус Vercel и конкретное поведение на `joinvyx.com`. `vercel inspect https://joinvyx.com --scope monnnomis-projects` помогает определить действующий деплой. CLI `vercel --prod --scope monnnomis-projects` — возможный отдельный путь при необходимости, а не второй обязательный деплой после Git push.
6. В результате различай: написано, проверено локально, применено к базе и опубликовано. Не сообщай «работает на сайте», если проверена только локальная версия.

Базовая опубликованная версия при подготовке передачи: `4a3e4d895991fd1fae95113ec6e25a5fef12e94b` — просмотры постов. Коммиты этой документации могут быть новее, не меняя работающий продукт. Всегда сверяй актуальное состояние перед следующей задачей.

Соседняя папка `../design-previews/vyx-extrafazant/` — отдельный непубликуемый макет по прежнему запросу владельца. Он не является новой версией продакшена.
