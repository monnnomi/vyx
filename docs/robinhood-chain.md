# Robinhood Chain: привязка кошелька

Этап 1 из плана перехода от VP к токенам. Готово: участник привязывает свой EVM-кошелёк к аккаунту VYX подписью сообщения. Токенов, контрактов и раздачи ещё нет.

## Сеть

Параметры взяты из официальной документации `docs.robinhood.com/chain/connecting` (проверено 20 ноября 2026).

| | Основная сеть | Тестовая сеть |
| --- | --- | --- |
| Chain ID | 4663 (`0x1237`) | 46630 (`0xB626`) |
| RPC | `https://rpc.mainnet.chain.robinhood.com` | `https://rpc.testnet.chain.robinhood.com` |
| Обозреватель | `https://robinhoodchain.blockscout.com` | `https://explorer.testnet.chain.robinhood.com` |
| Газ | ETH | ETH |

Публичные RPC ограничены по частоте и не рекомендованы Robinhood для продакшена; для контрактов и раздачи нужен ключ провайдера (Robinhood советует Alchemy).

Выбор сети для сообщения о входе — переменная окружения `VYX_CHAIN_ID` (`4663` по умолчанию, `46630` для теста). Адрес кошелька один и тот же в обеих сетях.

## Как работает привязка

1. Профиль → «Connect wallet». Браузер берёт адрес из кошелька (`eth_requestAccounts`).
2. Сервер (`action=wallet-challenge`) сам составляет сообщение Sign-In with Ethereum (EIP-4361): домен, адрес, Chain ID, одноразовый nonce, срок 10 минут — и сохраняет его в `wallet_challenges`.
3. Кошелёк подписывает сообщение (`personal_sign`). Это бесплатно и не переводит средства.
4. Сервер (`action=wallet-link`) берёт сохранённое сообщение, восстанавливает адрес из подписи и сравнивает с запрошенным. Текст сообщения из браузера не принимается.

Проверка подписи — `server/evm.js`: Keccak-256, восстановление ключа secp256k1, EIP-191, EIP-55, без сторонних пакетов. Сверено с опубликованными векторами, с Node (`secp256k1` ECDH) и с подписями, сделанными независимой библиотекой.

## Правила

- Один кошелёк на аккаунт и один аккаунт на кошелёк.
- Кошелёк, который когда-либо был привязан к другому аккаунту, нельзя привязать снова (защита от передачи адресов между аккаунтами перед раздачей).
- После отвязки другой адрес можно привязать через 7 дней; прежний — сразу.
- Каждое действие пишется в `wallet_link_events`.
- Не больше 20 запросов на подпись в час на аккаунт; общие ограничения записи действуют.
- Кошельки на смарт-контрактах (длинные подписи EIP-1271/6492) пока не поддерживаются — проверка таких подписей требует обращения к сети.
- Адрес виден только владельцу аккаунта; в публичном профиле его нет.

## База

Таблицы `wallet_challenges`, `user_wallets`, `wallet_link_events` (`db/schema.sql`). Миграция `scripts/migrate-wallets.mjs` повторяемая; `deploy/zomro/deploy.sh` запускает её при выкладке.

## Ограничения этапа

- Подключение работает с кошельками, встроенными в браузер: расширения (MetaMask и другие) и встроенные браузеры приложений кошельков. Обычный мобильный Safari или Chrome без кошелька получает ссылку «Open in MetaMask». WalletConnect не подключён — для него нужен внешний пакет и ключ проекта.
- Поддерживает ли Robinhood Wallet подпись сообщений для сайтов, в документации Robinhood не указано. Проверить вручную на телефоне.

## Следующий этап
