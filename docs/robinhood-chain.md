# Robinhood Chain: привязка кошелька

Этап 1 из плана перехода от VP к токенам. Готово: участник привязывает свой EVM-кошелёк к аккаунту VYX подписью сообщения. Токенов, контрактов и раздачи ещё нет.

## Сеть

Параметры взяты из официальной документации `docs.robinhood.com/chain/connecting` (проверено 20 ноября 2026).

| | Основная сеть | Тестовая сеть |
| --- | --- | --- |
| Chain ID | 4663 (`0x1237`) | 46630 (`0xB626`) |
| RPC | `https://rpc.mainnet.chain.robinhood.com` | `https://rpc.testnet.chain.robinhood.com` |
| Обозреватель | `https://robinhoodchain.blockscout.com` | `https://explorer.testnet.chain.robinhood.com` |
| Газ | ETH | ETH |

Публичные RPC ограничены по частоте и не рекомендованы Robinhood для продакшена; для контрактов и раздачи нужен ключ провайдера (Robinhood советует Alchemy).

Выбор сети для сообщения о входе — переменная окружения `VYX_CHAIN_ID` (`4663` по умолчанию, `46630` для теста). Адрес кошелька один и тот же в обеих сетях.

## Как работает привязка

1. Профиль → «Connect wallet». Браузер берёт адрес из кошелька (`eth_requestAccounts`).
2. Сервер (`action=wallet-challenge`) сам составляет сообщение Sign-In with Ethereum (EIP-4361): домен, адрес, Chain ID, одноразовый nonce, срок 10 минут — и сохраняет его в `wallet_challenges`.
3. Кошелёк подписывает сообщение (`personal_sign`). Это бесплатно и не переводит средства.
4. Сервер (`action=wallet-link`) берёт сохранённое сообщение, восстанавливает адрес из подписи и сравнивает с запрошенным. Текст сообщения из браузера не принимается.

Проверка подписи — `server/evm.js`: Keccak-256, восстановление ключа secp256k1, EIP-191, EIP-55, без сторонних пакетов. Сверено с опубликованными векторами, с Node (`secp256k1` ECDH) и с подписями, сделанными независимой библиотекой.

## Правила

- Один кошелёк на аккаунт и один аккаунт на кошелёк.
- Кошелёк, который когда-либо был привязан к другому аккаунту, нельзя привязать снова (защита от передачи адресов между аккаунтами перед раздачей).
- После отвязки другой адрес можно привязать через 7 дней; прежний — сразу.
- Каждое действие пишется в `wallet_link_events`.
- Не больше 20 запросов на подпись в час на аккаунт; общие ограничения записи действуют.
- Кошельки на смарт-контрактах (длинные подписи EIP-1271/6492) пока не поддерживаются — проверка таких подписей требует обращения к сети.
- Адрес виден только владельцу аккаунта; в публичном профиле его нет.

## База

Таблицы `wallet_challenges`, `user_wallets`, `wallet_link_events` (`db/schema.sql`). Миграция `scripts/migrate-wallets.mjs` повторяемая; `deploy/zomro/deploy.sh` запускает её при выкладке.

## Ограничения этапа

- Подключение работает с кошельками, встроенными в браузер: расширения (MetaMask и другие) и встроенные браузеры приложений кошельков. Обычный мобильный Safari или Chrome без кошелька получает ссылку «Open in MetaMask». WalletConnect не подключён — для него нужен внешний пакет и ключ проекта.
- Поддерживает ли Robinhood Wallet подпись сообщений для сайтов, в документации Robinhood не указано. Проверить вручную на телефоне.

## Контракты (этап 2, тестовая сеть)

Папка `contracts/` (Foundry). На сайт не выкладывается.

- `src/VYXToken.sol` — младший токен. Ровно 100 000 000, всё выпускается один раз на кошелёк казны. Нет владельца, допечатки и налога на переводы.
- `src/VYXDistributor.sol` — раздача по сезонам:
  - Сервер считает доли и публикует Merkle-корень сезона (`server/merkle.js`). Участник забирает токены сам, одной транзакцией за любое число сезонов.
  - Разблокировка равными частями: `tranches=1` — сразу всё; `tranches=4`, `interval=30 days` — по 25% в месяц.
  - Сервисный сбор с транзакции клейма в ETH (`claimFee`). Решение владельца: $0,03. Потолок в коде — 0,0001 ETH. Сбор копится в контракте; `withdrawFees()` отправляет его на `feeRecipient`.
  - Владелец не может забрать токены, уже распределённые по сезонам, а сезон нельзя опубликовать без пополнения контракта.
- `test/VYXDistributor.t.sol` — тесты. Merkle-дерево в них построено `server/merkle.js`, поэтому тесты заодно проверяют, что сервер и контракт хешируют одинаково.
- `script/Deploy.s.sol` — деплой обоих контрактов.

При расчётном курсе $1 500 за ETH комиссия $0,03 за одну транзакцию клейма составляет **0,00002 ETH** (`20000000000000` wei). Это значение по умолчанию при развёртывании. Его можно переопределить через `CLAIM_FEE_WEI`. Для уже развёрнутого контракта владелец меняет ставку вызовом `setClaimFee`. При изменении курса новая ставка в wei рассчитывается как `0.03 / цена ETH в долларах × 10^18`.

Сборка и тесты на Mac (в Терминале):

```
curl -L https://foundry.paradigm.xyz | bash   # затем открыть новый Терминал
foundryup
cd contracts
forge install --no-git foundry-rs/forge-std OpenZeppelin/openzeppelin-contracts@v5.1.0
forge test -vv
```

Деплой в тестовую сеть (тестовый ETH — с крана Robinhood Chain). Ключ хранится в зашифрованном хранилище Foundry, не в файлах и не в истории команд:

```
cast wallet import vyx-deployer --interactive
TOKEN_NAME="..." TOKEN_SYMBOL="..." TREASURY=0x... OWNER=0x... FEE_RECIPIENT=0x... CLAIM_FEE_WEI=20000000000000 \
  forge script script/Deploy.s.sol --rpc-url robinhood_testnet --account vyx-deployer --broadcast
forge verify-contract <адрес> src/VYXToken.sol:VYXToken --verifier blockscout --verifier-url https://explorer.testnet.chain.robinhood.com/api
```

Газ сети получает оператор Robinhood Chain; приложению доля газа не платится. Доход VYX с транзакций — сбор при клейме и комиссии пула ликвидности.

## Раздача jVYX (этап 3)

Решения владельца 21 ноября: ноябрьский фарм 17,5M, декабрьский 35M, раздача ранним участникам 10M (снимок — 22 ноября 00:00 UTC), разлочка всех сезонов ежедневно, 90 дней.

| Сезон | Пул | Кто и как | Считать после |
| --- | --- | --- | --- |
| `early-members` | 10M | зарегистрированы и имели VP до снимка; половина поровну, половина по VP | 22.11.2026 00:00 UTC |
| `season-1` | 17,5M | по VP сезона `season-1` | 01.12.2026 00:00 UTC |
| `season-2` | 35M | по VP сезона `season-2` | 25.12.2026 00:00 UTC |

Доли замораживаются один раз и больше не пересчитываются. Кто привяжет кошелёк позже, попадает в следующую партию того же сезона с тем же графиком разлочки и ничего не теряет.

Порядок на сервере (`scripts/token-season.mjs`):

1. `allocate <season>` — заморозить доли.
2. `batch <season> [--start=ISO]` — Merkle-партия для привязанных кошельков. Скрипт печатает команды для владельца: перевести токены из казны в распределитель и вызвать `addSeason`.
3. `activate <batchId> <onchainId>` — сервер сверяет корень, сумму и график с контрактом в сети и только тогда показывает партию участникам.
4. `status` — сводка; `discard <batchId>` — удалить партию, которую не добавили в сеть.

Участник видит карточку «VYX Junior» в профиле, только когда у него есть доля. Клейм — одна транзакция за все живые сезоны, сбор 0,00002 ETH.
